# Gift Tracking — апгрейд: логин в Telegram, автосообщения владельцам, цены Gift Satellite, меню настроек

Дата: 2026-08-14
Репозиторий: https://github.com/pexepo/gifttracking.git

## Проблемы, которые решаем

1. **Логин только через консоль.** Неудобно: нужно заходить на сервер и вводить номер/код. Нужен логин прямо в Telegram.
2. **Автосообщения не приходят владельцам подарков.** Бот не пишет владельцу при появлении нового уникального подарка; часть уведомлений о новых гифтах теряется.
3. **Нет цен от @gift_satellite_bot.** Пользователь вводит API-ключ (выдаётся ботом), бот получает цены со всех маркетов на подарок с конкретной моделью и фоном. URL API у пользователя нет — находит реверс мини-аппа.
4. **Нет единого меню** фильтров и настроек (сейчас только `/filters`).

## Подход

Эволюция текущего кода (Python 3.11+, Telethon для MTProto + голый Bot API через `urllib`). Ничего не переписываем: монитор, каталог, хранилище остаются; добавляем модули `login.py` и `pricing.py`, расширяем `notifier.py`/`monitor.py`.

## Архитектура

```
gift_tracking/
  config.py        + satellite_api_key, satellite_api_url (env-дефолты)
  models.py        + новые поля фильтров, BotSettings, PriceInfo
  storage.py       + настройки: шаблон, ключ, url, переключатели
  telegram_api.py  + send_message_to_user() — ЛС владельцу через MTProto
  notifier.py      + share-phone клавиатура, инлайн-цифровая клавиатура, сообщения меню
  pricing.py       НОВЫЙ — клиент веб-API Gift Satellite (URL + ключ настраиваются)
  login.py         НОВЫЙ — конечный автомат логина через бота (phone → code → 2FA)
  monitor.py       оркестрация: логин при старте, цена+ЛС владельцу в алерте, /menu
```

## 1. Логин через Telegram (без консоли)

Поток авторизации MTProto-аккаунта целиком через бота:

1. **Старт** — если сессия не авторизована, бот отправляет сообщение с reply-клавиатурой с одной кнопкой **«📱 Поделиться номером»** (`request_contact=True`).
2. **Номер получен** → `client.send_code_request(phone)`; бот показывает инлайн-клавиатуру с цифрами: `1..9`, `0`, «⌫», «Отправить». Код можно вводить кнопками или текстом.
3. **Код принят** — аккаунт авторизован, сессия сохранена, бот подтверждает.
4. **2FA** — если включён пароль, бот просит ввести пароль текстом.
5. **Уже авторизовано** — сессия валидна, логин пропускается, бот показывает статус.

Реализация: `login.py` — конечный автомат с состояниями `PHONE → CODE → PASSWORD → DONE`, ожидание ответа через Bot API `getUpdates`. `FloodWait`/ошибки — бот пишет причину и предлагает повторить. Отмена — `/cancel`.

Особенности:
- Номер из контакта нормализуется (убираем пробелы/`+`/скобки).
- Если сессия есть, но невалидна — предлагается перелогиниться без удаления файла (Telethon перезапишет).
- Таймаут ожидания ответа (10 минут) с автоповтором запроса.

## 2. Автосообщения владельцам + цены

При обнаружении нового уникального подарка вместо «просто уведомление в чат»:

1. **Фильтры** — как сейчас (username, blacklist, фоны) + новые: фильтр по моделям и диапазон цены (мин/макс).
2. **Цена** — `pricing.py` запрашивает цену для модели+фона коллекции. Если ключ не задан или API недоступен — цена пропускается, алерт не блокируется.
3. **Шаблон** — редактируемый текст с плейсхолдерами: `{title}`, `{number}`, `{model}`, `{backdrop}`, `{price}`, `{link}`.
4. **Отправка владельцу** — через MTProto от зарегистрированного аккаунта (`send_message` на `owner_id`).
5. **Оповещение админу** — ✅ отправлено / ❌ не удалось (причина: пользователь запретил ЛС, flood и т.п.); подарок помечается обработанным, чтобы не дублировать.

Исправление «не все сообщения приходят»: отправка идёт напрямую через MTProto (устойчивее к сбоям Bot API), сетевые ошибки фиксируются в логах и не теряются молча. `send_pending_notifications` получает обработку: попытка → успех/провал → `mark_notified(slug)` в обоих случаях с записью статуса.

## 3. Клиент цен Gift Satellite (`pricing.py`)

- Ключ и URL задаются в меню настроек (env-дефолты `SATELLITE_API_KEY`, `SATELLITE_API_URL`).
- URL и формат ответа конфигурируемые: если эндпоинт меняется, правится один модуль.
- `fetch_price(collection, model, backdrop) -> PriceInfo | None` — цены по маркетам (TON/Stars). Ошибка API не роняет монитор.
- «Проверить ключ» в настройках — тестовый запрос и ответ «ключ работает»/«ошибка».

### Поиск URL (реверс мини-аппа) — во время реализации

1. Открыть `RequestAppWebView` для @gift_satellite_bot через залогиненный MTProto → получить URL мини-аппа.
2. Вытащить JS-бандл, найти домен API и эндпоинт цен.
3. Прописать базовый URL в клиенте и в настройки.

Fallback, если реверс не удаётся (защита/токен): пользователь открывает мини-апп в веб-Telegram с DevTools и скидывает 2-3 запроса из Network — по ним допиливается клиент.

## 4. Меню фильтров и настроек

Единая точка входа — `/menu`, `/filters` остаётся синонимом. Всё редактируется inline-кнопками из Telegram, хранится в SQLite (таблица `settings`), переживает перезапуск.

**⚙️ Фильтры** (подменю):

- ЛС владельцу: только @username / все владельцы (есть)
- Blacklist username (есть)
- Фоны: вкл/выкл + список (есть)
- Модели: вкл/выкл + список (новое)
- Цена: мин/макс (новое)

**🛠 Настройки** (подменю):

- Шаблон сообщения владельцу (текст + плейсхолдеры)
- API-ключ Gift Satellite (ввод + «проверить»)
- База URL API (смена эндпоинта)
- Переключатели: «авто-цена в алертах», «отправка владельцу»
- Статус аккаунта + «перелогиниться»

**👤 Аккаунт**:

- Статус логина, маскированный номер
- Кнопки «Выйти» / «Залогиниться»

Меню обновляется на месте через `editMessageText`, инлайн-кнопками, паттерн как в текущем `_filter_menu_keyboard`.

## 5. Модель данных

`RuntimeFilters` расширяется:

- `model_filters: tuple[str, ...]`, `model_filter_enabled: bool`
- `min_price: float | None`, `max_price: float | None`

Новые ключи в таблице `settings` (через JSON, как `runtime_filters`):

- `owner_message_template` (строка с плейсхолдерами)
- `satellite_api_key` (строка)
- `satellite_api_url` (строка, дефолт — обнаруженный при реверсе)
- `auto_price_enabled` (bool, дефолт true)
- `send_to_owner_enabled` (bool, дефолт true)

Новый dataclass: `PriceInfo` — карта `маркет → цена` (TON/Stars), рядом с `GiftEvent`.

## 6. Обработка ошибок

- Отправка владельцу: ловим ошибки Telethon (`ChatWriteForbiddenError` и пр.) → статус «❌ не отправлено: причина», `mark_notified` чтобы не спамить повторно.
- Ценовой API: любые ошибки сети/HTTP → `None`, лог, алерт идёт без цены.
- Логин: повторный ввод кода/пароля при неверном значении, таймаут ожидания, `/cancel`.

## 7. Тесты

unittest (`python -m unittest discover -s tests -v`), следуем стилю репозитория:

- Легенда шаблона с плейсхолдерами
- Ценовой клиент с фейковым HTTP-сервером (urlopen моки)
- Конечный автомат логина (переходы состояний)
- Меню/новые фильтры (рендер клавиатур)
- Отправка владельцу с моком MTProto

## 8. Запуск

Без изменений: `gift-tracking` (логин сам запросится через бота при старте). `.env` — опциональные новые переменные.
